2. Redis 主从模式

Redis 主从模式，也叫主从复制或 master-replica 复制，是指一个 Redis 实例作为主节点（master）负责处理写请求和部分读请求，一个或多个从节点（replica，早期称 slave）通过配置 replicaof 或启动命令连接主节点，持续接收并执行主节点传播过来的写命令，从而保持数据副本与主节点大致一致；从节点默认是只读的（replica-read-only yes），这样可以把读流量分散到多个从节点，实现读写分离、读扩展、数据备份和一定程度的故障恢复能力。

复制建立时，从节点会向主节点发送 PSYNC 命令并带上自己记录的复制 ID（replid）和复制偏移量（offset），主节点若判断可以进行部分重同步，就从复制积压缓冲区（repl-backlog）中把从节点缺失的那部分命令补发过去；如果无法部分重同步，则触发全量同步：主节点 fork 一个子进程生成当前数据的 RDB 快照，同时把生成期间新收到的写命令缓存起来，然后把 RDB 发送给从节点，从节点先清空自身数据并载入 RDB，再执行缓存中的增量命令，之后进入持续的命令传播阶段，主节点每执行一条写命令就异步发给所有从节点。

主从之间还会通过心跳和偏移量确认来监测连接与复制进度，网络短暂断开后如果条件满足可基于 backlog 做部分重同步，否则再次全量同步。需要注意的是，Redis 主从复制默认是异步的，因此从节点数据可能落后于主节点，主节点故障时也可能丢失最后一部分未同步的写入；主从模式本身只解决复制和读扩展，不负责自动选主和故障转移，通常要配合 Redis Sentinel 哨兵或 Redis Cluster 集群来实现高可用，由哨兵监控主从、在主观下线与客观下线判定后提升某个从节点为新主并让其他从节点复制新主；此外还可以使用级联复制让从节点再带从节点，以减轻主节点的复制压力。

总体来说，主从模式是 Redis 高可用和分布式架构的基础，适合读多写少、需要冗余备份和读负载均衡的场景，但使用时必须接受异步复制带来的延迟与一致性权衡，并合理配置持久化、复制积压缓冲区、超时和只读策略。

3. Redis 哨兵模式

Redis 哨兵模式（Redis Sentinel）是在主从复制基础上实现高可用的方案，它本身不存储业务数据，而是由一组独立的 Sentinel 进程组成，通常部署奇数个（如 3 个或 5 个）并分布在不同机器或故障域，持续监控主节点和从节点。

每个 Sentinel 会定期向节点发送 PING，如果在 down-after-milliseconds 内没有收到有效响应，就先把该节点标记为主观下线（SDOWN）；当达到配置的 quorum 个 Sentinel 都认为主节点不可达时，主节点被判定为客观下线（ODOWN），随后 Sentinel 之间进行选举，选出一个领头 Sentinel 负责故障转移。

领头 Sentinel 会从从节点中按优先级、复制偏移量、运行 ID 等规则挑选一个提升为新主，让其他从节点改为复制新主，并通过发布订阅机制通知客户端新的主节点地址；旧主恢复后会被降级为从节点。哨兵模式解决了主从模式不能自动选主和切换的问题，但数据复制仍是异步的，故障切换期间可能丢失少量写入，客户端也需要支持 Sentinel 或通过代理接入；它适合高可用和读写分离场景，但不等同于 Redis Cluster 的分片扩展。

4. 后渗透

拿到 Redis 未授权+主从复制 Module RCE 的反弹 shell 后，后渗透的核心思路是把 Redis 的“写文件”能力继续武器化，并结合系统层面做提权、持久化和隐藏。

首先确认权限和环境：id、whoami、是否在容器、Redis 以什么用户运行、有无 Docker socket、sudo 权限、SUID 文件、可写目录等。

如果 Redis 以 root 运行或容器内是 root，基本直接提权成功；否则找 SUID、sudo 配置、内核漏洞或可写服务配置提权。持久化方面，最直接的是利用 Redis 的 CONFIG SET dir + dbfilename 配合 BGSAVE 或主从复制下发任意文件，往 /root/.ssh/authorized_keys 写 SSH 公钥、往 /var/spool/cron/root 或 /etc/cron.d/ 写定时任务、往 Web 目录写 webshell、往 systemd 目录写服务，或者直接 useradd 加用户并加入 sudo 组。隐藏方面，可以替换 ps、top、netstat、ss 等命令过滤关键字，清理 Redis 日志、.bash_history、auth.log、wtmp/utmp，把后门文件放到 /dev/shm 或 /tmp 并改名，用 bind mount 或 rootkit 隐藏文件与进程，甚至用 LD_PRELOAD 劫持系统调用。

总之，Redis 未授权后渗透就是围绕“写文件”和“命令执行”两个能力，根据目标环境选择写公钥、写 cron、写 webshell、加用户或提权，最后清理痕迹并隐藏后门。
