一、基础知识

1. 文件头

文件头（File Header），也称为魔数（Magic Number） 或文件签名（File Signature），是文件开头的一段固定字节序列，用于标识文件的真实格式。它比文件后缀名更可靠，因为后缀可以被轻易修改。

2. 图片隐写的常用工具

file

Linux 自带的工具，用于快速查看文件类型。只能读取文件头部特征识别单一文件类型，无法检测文件末尾追加的隐藏数据。

Binwalk

一个自动提取文件系统的工具。最大优点是可自动完成指定文件的扫描，智能发掘潜藏在文件中所有可疑的文件类型及文件系统。

相比 file 命令：file 只从文件第一个字节开始识别，且通常只能把一个文件识别成一个类型，很难看出是否隐藏其他文件；Binwalk 能很好地完成这类任务。

快速提取文件命令：binwalk -e 文件名称

补充知识点：-e 是 --extract，表示自动提取扫描到的内嵌文件；-Me 常用组合，递归提取。Kali 默认自带 Binwalk，常用于固件分析、CTF 文件追加隐写（图种）。

foremost

基于文件开始格式、文件结束标志和内部数据结构进行恢复文件的程序。它通过分析不同类型文件的头、尾和内部数据结构，与镜像文件的数据进行比对，以还原文件。

默认支持 19 种类型文件的恢复，用户还可以通过配置文件扩展支持其他文件类型。有时候 Binwalk 无法正确分离出文件，可以尝试使用 foremost 分离。

常用命令：foremost -i 源文件 -o 输出目录

dd

半自动化工具。前面两种是自动化分离工具，当自动化工具不能实现文件分离时，可以用 dd 来手动分离。

常用命令：dd if=源文件名 bs=1 skip=开始分离的字节数 of=目标文件名

  • if：input file 输入文件
  • bs：block size 单次读取字节大小，bs=1 代表按单字节读取
  • skip：跳过前面多少字节开始读取

Stegsolve

CTF 中最常用来检测 LSB 隐写痕迹的Java图形工具。它可以对图片进行多种操作，查看不同比特位平面、通道提取、XOR、SUB等运算。

  • File Format：文件格式，主要查看图片的具体信息。
  • Data Extract：数据抽取，抽取图片中隐藏的LSB/MSB数据。
  • Frame Browser：帧浏览器，主要对 GIF 之类的动图进行分解。
  • Image Combiner：拼图，图片拼接。

注意：StegSolve是GUI程序，WSL终端无法直接调用；Windows下使用java -jar StegSolve.jar启动。LSB提取核心配置：勾选R/G/B通道bit0，Bit Order改为LSB First。

Stegdetect

主要用于分析 JPEG 文件，可以检测通过 JSteg、JPHide、OutGuess、Invisible Secrets、F5、appendX 和 Camouflage 等隐写工具隐藏的信息。属于老旧工具，现代CTF使用变少。

Stegdetect 通过统计测试来分析图像文件中是否包含隐藏内容。它运行静态测试以判断隐藏内容是否存在，此外还会尝试识别隐藏内容是通过哪个隐写工具嵌入的。

常用命令：stegdetect -s 10.0 文件名

png-dimensions-bruteforcer（PCRT/IHDR爆破工具统称）

专门针对PNG IHDR宽高篡改题目。PNG头部IHDR块存储宽高，篡改宽高后会造成图片只显示半截，同时IHDR块CRC校验失效。工具自动遍历宽高范围，计算CRC32匹配原始校验值，自动修复IHDR并输出完整PNG。

3. 图片的基本概念

数字图像

计算机中的图片本质上是一个数字化的像素矩阵。现实中的连续图像经过采样、量化和编码后，变成离散的二进制数据。图片隐写、图片分析、文件分离，本质上都是在操作这些二进制数据。

像素

像素是图像的最小组成单位。每个像素保存一个或多个颜色分量。例如 24 位 RGB 图像中，一个像素由 R、G、B 三个分量组成，每个分量通常占 8 位。

分辨率

分辨率表示图像的宽和高，例如 1920×1080。总像素数为“宽 × 高”。分辨率越高，图像越清晰，数据量也越大，通常可用于隐藏信息的空间也越大。

色彩深度 / 位深

位深表示每个像素用多少 bit 来表示颜色。位深越高，能表示的颜色越多，文件通常也越大。

位深 每像素 bit 颜色数 常见说明
1 位 1 2 二值图像，只有黑和白
8 位 8 256 灰度图或索引色图像
24 位 24 约 1677 万 真彩色，R/G/B 各 8 位
32 位 32 约 1677 万 + 透明度 常见为 RGBA，A 表示 Alpha 透明度

颜色通道

通道是颜色分量的存储方式。常见有：

  • RGB：红、绿、蓝三通道；
  • RGBA：RGB 加 Alpha 透明度通道；
  • 灰度：单通道；
  • YCbCr：亮度 Y 和两个色度通道 Cb、Cr。

图片隐写中，经常针对某一个通道或通道之间的差异进行分析，例如 LSB 隐写。

颜色模式

颜色模式描述图像如何表示颜色：

  • RGB：屏幕显示常用，加色模式；
  • CMYK：印刷常用，减色模式；
  • 灰度：只有亮度信息；
  • 索引色：像素存的是调色板索引，不是真实颜色值；
  • YCbCr：JPEG 压缩过程中常用的中间颜色空间。

位图与矢量图

位图由像素点阵组成，例如 BMP、PNG、JPEG、GIF，缩放后容易失真。矢量图由几何图形描述，例如 SVG，缩放不失真。图片隐写通常针对位图，因为位图有大量可操作的像素数据。

有损压缩与无损压缩

  • 无损压缩：解压后能完全恢复原图，例如 PNG、GIF、BMP、部分 TIFF；
  • 有损压缩：解压后不能完全恢复原图，例如 JPEG。

图片隐写时要注意：如果图像经过有损压缩，隐藏数据可能被破坏；所以很多 LSB 隐写更常出现在 PNG、BMP 等无损格式中。

调色板 / 索引色

GIF、PNG-8 等格式会把颜色保存在调色板中，像素数据只存索引值。调色板顺序、索引值、未使用颜色等都可能成为隐写或异常分析的位置。

扫描行与步长

图像数据通常按行存储。某些格式为了对齐，会在每行末尾填充额外字节。例如 BMP 每行字节数通常按 4 字节对齐，不足时补 00。这些填充字节不是像素，但分析文件时不能忽略。

通道顺序与像素排列

不同格式的通道顺序可能不同。例如 BMP 常见存储顺序是 BGR，而 PNG 常见是 RGB 或 RGBA。像素排列也可能有自上而下或自下而上的区别。分析图片数据时，这些细节会影响提取结果。

常见图片格式与隐写关系

格式 压缩方式 主要特点 隐写常见切入点
BMP 通常不压缩 结构简单，像素数据直观 LSB、行填充、附加数据
PNG 无损压缩 块结构，支持 Alpha 数据块、LSB、调色板、附加数据
JPEG 有损压缩 DCT 变换，APPn 元数据多 DCT 系数、APPn、量化表、附加数据
GIF 无损索引色 调色板、多帧 调色板、帧分解、LSB、附加数据
TIFF 可无损可有损 标签结构复杂 标签、附加数据、像素排列

总结

图片的基本概念核心是：像素、分辨率、位深、通道、颜色模式、压缩方式。理解这些之后，才能判断图片数据如何存储、隐写可能藏在哪里，以及为什么有些隐写只能用于 PNG/BMP，而有些则针对 JPEG 的 DCT 系数或 APPn 段。

二、JPG图片隐写

1. JPG的文件结构

以一幅24位（即RGB）彩色图像为例，JPEG的压缩分为四个步骤：

  • 颜色转换：在将彩色图像进行压缩之前，必须先对颜色模式进行数据转换。转换完成之后还需要进行数据采样。
  • DCT变换：是将图像信号在频率域上进行变换，分离出高频和低频信息的处理过程，然后再对图像的高频部分（即图像细节）进行压缩。
  • 量化：由于下面第四步编码过程中使用的码本都是整数，因此要对频率系数进行量化，将之转换为整数。数据量化后，矩阵中的数据都是近似值，和原始图像数据之间有了差异，这一差异是造成图像压缩后失真的主要原因。
  • 编码：编码是基于统计特性的方法。

四个步骤都完成后的JPEG文件，其基本数据结构为两大类型：段和经过压缩编码的图像数据。

PS:

  • 有些段没有长度描述也没有内容，只有段标识和段类型。文件头和文件尾均属于这种段。
  • 段与段之间无论有多少 FF 都是合法的，这些 FF 称为「填充字节」，必须被忽略掉。

JPEG文件使用的数据存储方式有多种。最常用的格式称为JPEG文件交换格式（JPEG File Interchange Format，JFIF），文件后缀名为jpg或jpeg。JPEG是有损压缩格式，将像素信息用JPEG保存成文件再读取出来，其中某些像素值会有少许变化。在保存时有个质量参数可在0至100之间选择，参数越大图片就越保真，但图片的体积也就越大。一般情况下选择70或80就足够清晰，和png图片相比，JPEG没有透明度信息。

数据段 值 名称
SOI 0xFFD8 图像开始
APP0 0xFFE0 JFIF应用资料块
APPn 0xFFE1 - 0xFFEF 其他的应用资料块(n, 1～15)
DQT 0xFFDB 量化表

DHT 0xFFC4 霍夫曼(Huffman)表

2. 常见的隐写方式

2.1 exif信息隐藏

可交换图像文件格式（英语：Exchangeable image file format，官方简称Exif），是专门为数码相机的照片设定的，可以记录数码照片的属性信息和拍摄数据。jpg图片拥有exif信息，可以通过填充exif信息来隐藏信息，其信息存储在jpg中的APP1段中

解决方法

  • 在windows右键点击图片，选择属性，可以查看部分的exif信息。
  • 在linux使用工具exiftool可以看到所有的exif信息。

2.2 字符附加

在附加式的图片隐写术中，我们通常是用某种程序或者某种方法在载体文件中直接附加上需要被隐写的字符串或其他信息，由于写入的位置对图片来说无关紧要，所以不会影响图片的正常打开和识别。

解决方法

  • 用16进制编辑器打开图片，查找和flag有关的字符，出现在文件末尾的可能性更大
  • 在linux下，使用strings命令，可以将文件中的所有字符串打印出来，strings命令在对象文件或二进制文件中查找可打印的字符串。字符串是4个或更多可打印字符的任意序列，以换行符或空字符结束。 strings命令对识别随机对象文件很有用。
  • 常用命令：strings 文件名称

2.3 文件结合

一种采用特殊方式将图片文件（如JPG格式）与其他文件结合起来的文件。该文件一般保存为JPG格式，可以正常显示图片，当有人获取该图片后，可以修改文件的后缀名，比如结合的是zip文件，将图片改为zip压缩文件，在文件无损坏的情况下就可以以zip文件直接打开。

图种是一种以图片文件为载体，然后将zip等压缩包文件附加在图片文件后面。因为操作系统识别的过程中是，从文件头标志，到文件的结束标志位，当系统识别到图片的结束标志位后，默认是不再继续识别的，所以我们在通常情况下只能看到它是只是一张图片。

解决方法

  • 在windows下修改后缀名或者16进制编辑器手工分离
  • 在linux下使用binwalk，dd, foremost工具分离文件

2.4 基于DCT域的JPG图片隐写

因为DCT是一种有损压缩（Loss Compression）技术，但一般不会影响图像的视觉效果，可以通过这个特性来隐藏信息。在这个隐写类型中，常见的隐写方法有JSteg、JPHide、Outguess、F5等等

解决方法

  • 使用Stegdetect检测隐写方式，并且还可以基于字典暴力破解密码方法提取通过Jphide、outguess等方式嵌入的隐藏信息。
  • 根据Stegdetect的判断结果，使用JSteg、JPHide、OutGuess、Invisible Secrets、F5等工具完成解密。

三、PNG图片隐写

1. PNG的文件结构

PNG 是一种无损压缩的位图片形格式，其设计目的是试图替代 GIF 和 TIFF 文件格式，同时增加一些 GIF 文件格式所不具备的特性。PNG 图像格式文件（或者称为数据流）由一个 8 字节的 PNG 文件署名（PNG file signature）域和按照特定结构组织的 3 个以上的数据块（chunk）组成。

PNG 定义了两种类型的数据块，一种是称为关键数据块（critical chunk），这是必需的数据块，另一种叫做辅助数据块（ancillary chunks），这是可选的数据块。关键数据块定义了 4 个标准数据块（IHDR、PLTE、IDAT、IEND），每个 PNG 文件都必须包含它们，PNG 读写软件也都必须要支持这些数据块。

PNG 文件签名（十六进制）：
89 50 4E 47 0D 0A 1A 0A
其中 50 4E 47 即 ASCII 的 PNG。

PNG图像文件中每一块数据块的格式都是相同的，分别由4个部分组成

字段名 大小（字节） 描述
Length（长度） 4 指定数据块中的数据长度
Chunk Type Code（数据块类型码） 4 数据块类型，例如IHDR、PLTE、IDAT等
Chunk Data（数据块数据） Length 存储数据
CRC（循环冗余检测） 4 循环冗余码

CRC循环冗余码生成的计算方式是通过对ChunK Type Code和Chunk Data中的数据进行计算得到的，计算方式如下：
$$\boldsymbol{CRC-32=x^{32}+x^{26}+x^{23}+x^{22}+x^{16}+x^{12}+x^{11}+x^{10}+x^{8}+x^{7}+x^{5}+x^{4}+x^{2}+x^{1}+1}$$

PNG 中常见的关键数据块：

数据块 类型码 名称 说明
IHDR 0x49484452 图像头 宽、高、位深、颜色类型、压缩方法等
PLTE 0x504C5445 调色板 索引色图像使用
IDAT 0x49444154 图像数据 实际压缩后的像素数据，可多个
IEND 0x49454E44 图像结束 文件结尾标志
tEXt 0x74455874 文本信息 可存储键值对文本
zTXt 0x7A545874 压缩文本 压缩后的文本信息

pHYs 0x70485973 物理像素 像素尺寸、宽高比等

IHDR

文件头数据块 IHDR（Header Chunk）：它包含有 PNG 文件中存储的图像数据的基本信息，由 13 字节组成，并要作为第一个数据块出现在 PNG 数据流中，而且一个 PNG 数据流中只能有一个文件头数据块

其中我们需要了解的是前 8 字节的内容，其中我们主要关注图片的宽和高，出题人经常会去更改一张图片的高度或者宽度使得一张图片显示不完整从而达到隐藏信息的目的。

字段名 大小（字节） 描述

PLTE

调色板数据块 PLTE（palette chunk）：它包含有与索引彩色图像（indexed-color image）相关的彩色变换数据，它仅与索引彩色图像有关，而且要放在图像数据块（image data chunk）之前。真彩色的 PNG 数据流也可以有调色板数据块，目的是便于非真彩色显示程序用它来量化图像数据，从而显示该图像。

一个PNG文件只能有一个调色板数据块，调色板数据块从下标0开始

数据块名称 允许多个数据块 作用
btRed 1 红色颜色值
btGreen 1 绿色颜色值
btBlue 1 蓝色颜色值

IDAT

图像数据块 IDAT（image data chunk）：它存储实际的数据，在数据流中可包含多个连续顺序的图像数据块。

特点如下：

  • 储存图像像素数据
  • 在数据流中可包含多个连续顺序的图像数据块
  • 采用 LZ77 算法的派生算法进行压缩
  • 可以用 zlib 解压缩

值得注意的是，IDAT 块只有当上一个块充满时，才会继续一个新的块。

IEND

PNG的图像结束数据（IEND）用来标记PNG文件结束，并且必须要放在文件的尾部。

一般情况下，所有PNG图像结束数据（IEND）的十六进制数值都是一样的，具体的数值如下：

00 00 00 00 49 45 4E 44 AE 42 60 82

IEND数据块的长度总是 00 00 00 00，数据标识总是 IEND（49 45 4E 44），因此，CRC码也总是 AE 42 60 82
出题人可能修改该结构，导致文件无法正常打开。

PNG 使用 DEFLATE（zlib）进行无损压缩，解码后能完全恢复原始像素。因为无损，所以非常适合 LSB 等像素级隐写。

与 JPG 相比：

  • PNG 没有 DCT 变换，不涉及有损量化；
  • 支持透明度（Alpha 通道）；
  • 文件通常比 JPG 大，但画质无损；
  • 隐写多发生在像素数据、调色板、文本块或附加数据中。

2. 常见的隐写方式

2.1 LSB 隐写

LSB 全称 Least Significant Bit，最低有效位。PNG 文件中的图像像素一般是由 RGB 三原色（红绿蓝）组成，每一种颜色占用 8 位，取值范围为 0x00 至 0xFF，即有 256 种颜色，一共包含了 256 的 3 次方的颜色，即 16777216 种颜色。而人类的眼睛可以区分约 1000 万种不同的颜色，意味着人类的眼睛无法区分余下的颜色大约有 6777216 种。

LSB 隐写就是修改 RGB 颜色分量的最低二进制位（LSB），每个颜色会有 8 bit，LSB 隐写就是修改了像素中的最低的 1 bit，而人类的眼睛不会注意到这前后的变化，每个像素可以携带 3 比特的信息。

解决方法：

  • 使用 Stegsolve 工具，通过 Data Extract 功能抽取 LSB 数据，可分别查看 R、G、B、Alpha 等通道的最低位平面。
  • 使用 zsteg 工具，专门用于 PNG/BMP 的 LSB 隐写检测，可自动尝试多种位平面和通道组合。
    常用命令：zsteg 文件名.png
  • 使用 Python 脚本（如 PIL、numpy）手动提取每个通道的最低位并重组为字节流。
  • 有时需要指定通道顺序（如 RGB、BGR）、位平面（如最低位、次低位）或扫描方向。

2.3 调色板隐写

对于使用索引色的 PNG（颜色类型为 3），像素数据存储的是调色板索引，而不是真实颜色值。调色板中可能包含未使用的颜色，或者调色板顺序、索引值可以被修改来隐藏信息。

解决方法：

  • 用 010 Editor 或 Python 解析 PLTE 块，查看调色板颜色数量和实际使用情况。
  • 检查调色板中是否有异常颜色、重复颜色或未使用的颜色项。
  • 修改调色板顺序或索引值可能隐藏数据，需对比原始图像或分析索引分布。

2.3 IDAT 块隐写 / 数据修改

IDAT 块存储经过 zlib 压缩的像素数据。隐写者可能：

  • 在 IDAT 数据中直接插入额外信息；
  • 修改压缩流，使解压后像素值发生微小变化；
  • 利用多个 IDAT 块之间的顺序或内容隐藏信息。

解决方法：

  • 使用 pngcheck 检查 PNG 文件完整性，查看 IDAT 块是否异常。
    常用命令：pngcheck -v 文件名.png
  • 用 Python 的 zlib 解压 IDAT 数据，分析原始像素，再重新压缩对比。
  • 用 binwalk 扫描是否有内嵌文件。

2.4 字符附加

与 JPG 类似，可以在 PNG 文件末尾（IEND 块之后）直接附加字符串或文件。图片仍能正常打开，因为 PNG 解析器在读到 IEND 后就停止解析。

解决方法：

  • 用 16 进制编辑器打开，拉到文件末尾，查找 flag、key 等关键字。
  • 使用 strings 文件名.png 提取所有可打印字符串。
  • 使用 grep -a "flag" 文件名.png 直接搜索。

2.5 文件结合（图种）

将 ZIP、RAR 等压缩包附加在 PNG 文件后面，形成“图种”。修改后缀为 .zip 或用 binwalk、foremost 分离即可。

解决方法：

  • Linux 下：binwalk -e 文件名.png 自动提取内嵌文件。
  • foremost -i 文件名.png -o 输出目录 进行分离。
  • 手动分离：用 dd 根据文件头偏移提取。
  • Windows 下可改后缀为 .zip 尝试打开。

2.6 文本块隐写（tEXt / zTXt / iTXt）

PNG 允许在文件中嵌入文本信息，这些信息可能包含提示、密码或 flag。可以用 exiftool 或 pngcheck 查看。

解决方法：

  • exiftool 文件名.png 查看所有元数据，包括文本块。
  • pngcheck -v 文件名.png 会列出所有块，包括 tEXt、zTXt、iTXt。
  • 用 010 Editor 的 PNG 模板查看文本块内容。
  • 有时文本被压缩（zTXt）或编码，需要手动解压/解码。

2.8 图片容差隐写

容差原本是颜色选取的阈值参数，取值范围为 0～255；容差数值越大，匹配的颜色范围越广。CTF 题目出现两张及以上同源图片时，优先考虑容差比对、盲水印这类图像差分类隐写。
原理：载体图与含密图绝大部分像素几乎一致，仅少量像素存在微弱差值，肉眼无法分辨，通过图像差分、设置容差阈值，就能把差异区域提取出来，得到隐藏信息。

  2. Photoshop
    将两张图层重叠，上层图层修改图层混合模式（差值 / 排除），再调整对比度、亮度放大微弱像素差，显现隐藏内容；上手门槛略高，但对差分、盲水印类题目适用性很强。

2.9 图层叠加

  1. Photoshop（图形化工具）
    打开 PSD 源文件，直接单独显示 / 隐藏各个图层，取出被遮挡的隐藏内容；也可以调整图层混合模式、不透明度做差分。
  2. Stegsolve（CTF 最常用）
    专门针对帧、通道、位平面，Frame Browser浏览多帧 GIF/APNG，切换各个通道、bit 平面，等效拆分图层，比赛首选。
  3. WSL 命令行现代化方案

  • gifsicle：提取 GIF 每一帧

  • imagemagick convert：拆分 APNG、PSD 图层

3.0 其他隐写方式

  • APNG 多帧：动态 PNG 可能将信息隐藏在某一帧中，可用 Stegsolve 的 Frame Browser 分解查看。

四、GIF隐写

1. GIF文件结构

GIF 图像文件以数据块 (block) 为单位来存储图像的相关信息。一个 GIF 文件由表示图形 / 图像的数据块、数据子块以及显示图形 / 图像的控制信息块组成，称为 GIF 数据流 (Data Stream)。数据流中的所有控制信息块和数据块都必须在文件头 (Header) 和文件结束块 (Trailer) 之间。

GIF 文件格式采用了 LZW (Lempel-Ziv-Walch) 压缩算法来存储图像数据，定义了允许用户为图像设置背景的透明 (transparency) 属性。此外，GIF 文件格式可在一个文件中存放多幅彩色图形 / 图像。如果在 GIF 文件中存放有多幅图，它们可以像幻灯片那样显示或者像动画那样演示。

2. 常见的隐写方式

GIF隐写按照隐藏信息的载体，可以分为三大类：基于文件结构隐写、基于空间轴隐藏信息、基于时间轴隐藏信息

2.1 基于文件结构隐写

不修改图像像素，通过操纵GIF文件各个数据块存放秘密信息。

  • 尾部追加隐写：在文件结束标记 0x3B 之后追加数据
  • 注释扩展块隐写：在Comment Extension扩展块存放明文flag，特征 0x21 0xFE
  • 应用程序扩展块隐写：在NETSCAPE2.0扩展块嵌入数据，特征 0x21 0xFF
  • 子块长度篡改、保留位篡改，制造解析错位隐藏数据
  • 全局/局部颜色表的冗余条目存放数据

2.2 基于空间轴隐藏信息

信息嵌入单帧图像内部，在像素/调色板RGB分量层面隐藏。

  • 调色板RGB分量LSB隐写（GIF最经典空间隐写）
  • 图像LZW压缩数据流内部嵌入信息
  • 单帧图像像素索引LSB隐写

2.3 基于时间轴隐藏信息

依托GIF多帧动画特性，帧与帧之间时序/叠加关系携带秘密，单独一帧无法得到完整信息。

  • 帧分离后叠加、异或多帧图片还原flag
  • 修改帧延迟时间，降低播放速度观察一闪而过的内容
  • 篡改帧处置方法（Disposal Method），改变帧渲染叠加逻辑
  • flag拆分在不同帧中，需要拼接全部帧内容

五、音频隐写

1. MP3文件格式

基础概念
MP3全称为MPEG Audio Layer 3，它是一种高效的计算机音频编码方案，它以较大的压缩比将音频文件转换成较小的扩展名为.mp3的文件，基本保持源文件的音质。

MP3音频压缩包含编码和解码两部分，编码是将原始信号转换成电平信号的过程，解码即是逆过程，MP3采用了感知音频编码（Perceptual Audio Coding）这一失真算法。人耳感受声音的频率范围是20Hz-20kHz，MP3截掉了大量的冗余信号和无关的信号，编码器通过混合滤波器组将原始声音变换到频率域，利用心理声学模型，估算刚好能被察觉到的噪声水平，再经过量化，转换成Huffman编码，形成MP3位流。解码器要简单得多，它的任务是从编码后的谱线成分中，经过反量化和逆变换，提取出声音信号。

帧头4字节，是MP3帧的标志；CRC 2字节可选；标准MP3通道附加信息固定32字节，之后是Huffman编码压缩音频数据，解码器逐帧解码播放。

CTF重点：MP3为有损压缩，存储的是频域压缩后的数据，不适合PCM采样LSB隐写，隐写多考察ID3标签、帧结构保留位、帧间隙隐藏文件。

2. WAV文件结构

WAVE 文件是非常简单的一种 RIFF 文件（资源互换文件格式），它的格式类型为WAVE。RIFF 块包含两个子块，这两个子块的 ID 分别是fmt和data，其中fmt子块由结构 PCMWAVEFORMAT 所组成，其子块的大小就是 sizeofof (PCMWAVEFORMAT)，数据组成就是 PCMWAVEFORMAT 结构中的数据。WAV 是最接近无损的音乐格式，所以文件大小相对也比较大。

Format chunk（fmt 子块）

以 'fmt ' 为标识，Size 表示该区块数据长度（不含 ID 和 Size 自身）。

名称 偏移 字节 端序 内容
ID 0x00 4 大端 ‘fmt ‘ = 0x666D7420
Size 0x04 4 小端 16（标准PCM）
AudioFormat 0x08 2 小端 音频格式，PCM=1
NumChannels 0x0A 2 小端 声道数
SampleRate 0x0C 4 小端 采样率
ByteRate 0x10 4 小端 每秒字节数 = 采样率×声道×位深/8
BlockAlign 0x14 2 小端 数据块对齐 = 声道×位深/8
BitsPerSample 0x16 2 小端 采样位数

Data chunk

Data块中存放的是音频的采样数据。每个sample按照采样的时间顺序写入，对于使用多个字节的sample，使用小端模式存放（低位字节存放在低地址，高位字节存放在高地址）。对于多声道的sample采用交叉存放的方式。例如：立体双声道的sample存储顺序为：声道1的第一个sample，声道2的第一个sample；声道1的第二个sample，声道2的第二个sample；依次类推……

名称 偏移地址 字节数 端序 内容
ID 0x00 4Byte 大端 'data' (0x64617461)
Size 0x04 4Byte 小端 N
Data 0x08 NByte 小端 音频数据

注：图片印刷笔误写为0x64617461前面的数字错印成0x64617461之外的值，data四个字符d(0x64)、a(0x61)、t(0x74)、a(0x61)，大端正确值：0x64617461

3. 隐写方式

3.1 摩斯密码

摩尔斯电码（又译为摩斯密码，Morse code）是一种时通时断的信号代码，通过不同的排列顺序来表达不同的英文字母、数字和标点符号，题目通过将摩斯电码的长短声音放入音频，从而达到隐写的效果
解决方式：

  • 使用 Audacity 观察音频的图像
  • 通过手动或者在线网站解密
  • https://morsecode.world/international/decoder/audio-decoder-adaptive.html

3.2 频谱隐写

频谱隐写是音频CTF高频考点。音频分为时域波形和频域频谱，时域只能看到音量大小，切换到频谱视图可以看到不同频率随时间的变化。将文字、二维码等信息绘制在音频高频区域，人耳无法感知，播放音频听不出异常，只有查看频谱图才能发现隐藏内容。

解决方式：

  • 使用 Audacity 打开音频，将视图切换为频谱图（ spectrogram），放大查看高频区域；
  • 若出现二维码：截图后使用二维码识别工具解码；
  • Linux 命令行工具 sox 也可导出音频频谱图片。

常见坑：默认打开Audacity是波形视图，必须手动切换到频谱视图；隐藏内容大多在高频段，需要放大上方频率区域。

3.3 波形隐写

波形隐写属于时域隐写，直接修改音频采样的振幅（波形高低），信息藏在波形轮廓上，频谱图不会有额外内容。一般用高低波形代表二进制0和1，或者在波形中嵌入条形码、标记点。

解决方式：

  • 使用 Audacity，保持默认波形视图，横向放大音频；
  • 观察波形振幅的规律变化，提取01二进制串；
  • 将二进制串按8bit分组，转换为ASCII字符得到flag。

区分要点：

  • 频谱隐写：看频域（频谱图）
  • 波形隐写：看时域（波形图）

3.4 基于LSB的音频隐写

仅适用于无损WAV（PCM）音频，MP3等有损压缩音频无法使用LSB隐写，压缩会破坏最低位信息。
原理：WAV文件的data块存储PCM采样值，采样二进制最低位LSB对声音影响极小，修改最低比特人耳几乎无法分辨。把flag的二进制数据依次写入每个采样的最低位；提取时读取每个采样的LSB比特，8bit一组转ASCII字符。

解决方式：

  • Python内置wave库编写脚本读取WAV采样，提取LSB比特；
  • 工具：stegolsb、wavsteg、steghide（带密码隐写）；

    注意：立体声WAV采样为交叉存储 L1 R1 L2 R2，编写脚本时要遵循采样顺序读取。
