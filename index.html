CSRF基础

post @ 2026-08-12

前言

  1. 在下面的题解中，没有特别强调时：SameSite:None
  2. 漏洞完成最终利用形式：钓鱼，在实际利用中最好找到一个方法将钓鱼形式csrf转化为无用户交互的csrf，进而提高危害

0x00.基础知识

  1. 什么是CSRF？
    跨站请求伪造（Cross-Site Request Forgery，简称 CSRF），是一种利用用户已登录的身份，在用户不知情的情况下，诱导其在第三方页面发起伪造请求，从而执行非预期操作（如改密码、转账、修改信息）的漏洞。即攻击者不偷你的账号密码，不读你的 Cookie，只是让你的浏览器 “带着你的身份，替你干坏事”。

  2. 漏洞由来：HTTP 无状态与 Cookie 的设计初衷

    • HTTP 协议本身是无状态的：每次请求都是独立的，网站无法直接识别用户身份。
    • 为了实现 “免重复登录”，诞生了Cookie + Session机制：用户登录后，网站会在浏览器中写入 Cookie，后续每次访问该网站，浏览器都会自动带上对应域名的 Cookie，网站通过 Cookie 识别用户身份。
    • 漏洞的根源：浏览器的 “自动带 Cookie” 机制，被跨站请求滥用 —— 第三方恶意页面发起的请求，浏览器依然会自动带上目标网站的 Cookie，网站无法区分请求是用户主动发起，还是被伪造的。

  3. CSRF 攻击的 3 个必备条件

    • 用户处于目标网站的有效登录状态（浏览器存有合法的会话 Cookie）；
    • 目标网站的敏感操作接口，仅依赖 Cookie 做身份校验，没有额外的请求合法性校验；
    • 浏览器允许跨站发起请求，并自动携带目标网站的 Cookie（这是浏览器的原生行为）。

对于cookie的字段认识
Cookie 所有标准字段完整对照表

字段名称 示例值 详细作用
Name=Value user_session=7s9k2p6d8f1g Cookie 核心主体，以键值对形式存储用户会话、身份标识、临时配置等数据，是网站识别用户的核心凭证。
Domain example.com 规定该 Cookie 归属的域名，默认是当前请求域名；设置后所有子域名都能携带、访问该 Cookie。
Path /admin 限制 Cookie 生效的网站路径，只有访问域名下该路径及子路径时，浏览器才会携带此 Cookie。
Expires Fri, 31 Dec 2026 23:59:59 GMT 绝对过期时间，设置固定日期时间；到达时间后浏览器自动删除该 Cookie，用于持久型 Cookie。
Max-Age 86400 相对过期时间，单位秒；从设置时刻开始倒计时，超时自动删除，优先级高于 Expires。
HttpOnly 无值（仅标记） 禁止前端 JavaScript 通过 document.cookie 读取和操作该 Cookie，防止 XSS 攻击窃取会话凭证。
Secure 无值（仅标记） 该 Cookie 仅在 HTTPS 加密请求中携带，HTTP 明文请求不会发送，避免中间人抓包窃取。
SameSite Strict / Lax / None 管控跨站请求时是否自动携带 Cookie，用来规范浏览器跨域身份凭证的发送行为。
Priority High / Medium / Low 浏览器存储空间不足时，按优先级淘汰 Cookie；高优先级最后被清理，保证重要会话 Cookie 留存。
Partitioned 无值（仅标记） 隔离第三方 Cookie，采用分区存储，防止跨网站追踪用户行为，适配现代浏览器隐私策略。
  • SameSite=Strict（比如 hook_slardar_session_id）：
    浏览器完全禁止跨站请求携带这个 Cookie。也就是说，只要请求是从其他域名发起的（比如恶意页面），浏览器绝不会带上这个 Cookie，直接防御 CSRF。
  • SameSite=None（比如 passport_csrf_token、ssid_ucp_v1）：
    浏览器不限制跨站携带，任何跨站请求（POST 表单、AJAX、GET 跳转）都会自动带上 Cookie。这是 CSRF 风险最高的设置，而且必须搭配 Secure 属性（截图里这些 Cookie 都同时开了 Secure，符合规范）。
  • 无显式设置（默认 Lax）（截图里大部分 Cookie 没标 SameSite，Chrome 80+ 默认值）：
    宽松限制：仅在「跨站顶级导航的 GET 请求」中携带 Cookie（比如点击恶意链接跳转到目标网站），跨站 POST 表单、AJAX 请求不会携带。
    这意味着：如果靶场的敏感操作是 GET 请求，Lax Cookie 依然能被 CSRF 利用；如果是 POST 请求，跨站表单就带不上 Cookie，攻击会失败。

在现在的网页中，网站会在用户会话中生成一个随机 Token，存在 Cookie 里，同时在表单 / 请求参数里也会带上这个 Token，提交请求时服务器会比对两者是否一致，直接防御 CSRF。

图像基础知识

图像基本概念

图像是人类视觉的基础，是自然景物的客观反映，是人类认识世界和人类本身的重要源泉。“图”是物体反射或透射光的分布，“像“是人的视觉系统所接受的图在人脑中所形成的印象或认识，照片、绘画、剪贴画、地图、书法作品、手写汉字、传真、卫星云图、影视画面、X光片、脑电图、心电图等都是图像。

在计算机中，按照颜色和灰度的多少可以将图像分为四种基本类型。

  • 二值图像

    一幅二值图像的二维矩阵仅由0、1两个值构成，“0”代表黑色，“1”代白色。由于每一像素（矩阵中每一元素）取值仅有0、1两种可能，所以计算机中二值图像的数据类型通常为1个二进制位。二值图像通常用于文字、线条图的扫描识别（OCR）和掩膜图像的存储。

  • 灰度图像

    灰度图像矩阵元素的取值范围通常为[0，255]。因此其数据类型一般为8位无符号整数的（int8），这就是人们经常提到的256灰度图像。**“0”表示纯黑色，“255”表示纯白色，中间的数字从小到大表示由黑到白的过渡色。**二值图像可以看成是灰度图像的一个特例。

  • 索引图像

    索引图像的文件结构比较复杂，除了存放图像的二维矩阵外，还包括一个称之为颜色索引矩阵MAP的二维数组。MAP的大小由存放图像的矩阵元素值域决定，如矩阵元素值域为[0，255]，则MAP矩阵的大小为256Ⅹ3，用MAP=[RGB]表示。MAP中每一行的三个元素分别指定该行对应颜色的红、绿、蓝单色值，MAP中每一行对应图像矩阵像素的一个灰度值，如某一像素的灰度值为64，则该像素就与MAP中的第64行建立了映射关系，该像素在屏幕上的实际颜色由第64行的[RGB]组合决定。也就是说，图像在屏幕上显示时，每一像素的颜色由存放在矩阵中该像素的灰度值作为索引通过检索颜色索引矩阵MAP得到。

  • 真彩色RGB图像

    RGB图像与索引图像一样都可以用来表示彩色图像。与索引图像一样，它分别用红（R）、绿（G）、蓝（B）三原色的组合来表示每个像素的颜色。但与索引图像不同的是，RGB图像每一个像素的颜色值（由RGB三原色表示）直接存放在图像矩阵中，由于每一像素的颜色需由R、G、B三个分量来表示，**M、N分别表示图像的行列数，三个M x N的二维矩阵分别表示各个像素的R、G、B三个颜色分量。**RGB图像的数据类型一般为8位无符号整形。注意：通道的顺序是 BGR 而不是 RGB。

    图像类型 通道数 像素值范围 主要特点 常见用途
    二值图像 1通道 0 或 1 每个像素只有黑与白两种值 形态学操作、二值化、轮廓检测
    灰度图像 1通道 0 到 255 每个像素表示灰度（亮度） 图像预处理、物体检测、人脸识别
    索引图像 1通道 0 到 255（索引） 像素值为颜色表的索引，颜色表决定实际颜色 存储压缩、较少颜色的图像表示
    RGB图像 3通道（R、G、B） 0 到 255 每个像素由红、绿、蓝三个通道组成 普通彩色图像显示、图像处理与分析

    简单的讲：图像是由像素点组成的，每个像素点的取值范围为: [0, 255] 。像素值越接近于0，颜色越暗，接近于黑色；像素值越接近于255，颜色越亮，接近于白色。

  • 重要概念HWC

    HWC 是图像的形状，分别表示图像的高、宽、通道数。
    HW可以认为决定了一个通道的“面积”（像素点的数量）大小，比如 H=200, W=200 表示图像的高为200，宽为200，每个通道的像素点数量为40000。
    C表示图像的通道数，其数量决定你是那种类型的图片（参考上面的表格），比如 C=3 表示是RGB图像。

  • 重要概念分辨率与刷新率

    分辨率是图像的宽和高（W x H），刷新率是屏幕每秒更新画面的次数（Hz）。

    分辨率决定了图像的”清晰度”或”总像素数”。常见命名有两种方式：

    • 带”p”的命名：数字表示垂直像素数，如 1080p = 1920 × 1080（约207万像素），720p = 1280 × 720（约92万像素）
    • 带”K”的命名：数字表示水平像素约几千，如 2K ≈ 2560 × 1440，4K ≈ 3840 × 2160（约829万像素，是1080p的4倍）

    刷新率决定了画面显示的”流畅度”。比如 60Hz 表示屏幕每秒刷新60次图像，120Hz 则表示每秒刷新120次。刷新率越高，动态画面越流畅，拖影越少。

    两者的关系：分辨率和刷新率通过”带宽”相互制约。显卡传输图像数据到显示器的带宽计算公式为：

    带宽 = 水平像素 × 垂直像素 × 刷新率 × 色深

    比如 1920×1080 @ 60Hz（8bit色深）需要的带宽约为：1920 × 1080 × 60 × 8 ≈ 1.0 Gbps；而 4K @ 120Hz 需要的带宽约为：3840 × 2160 × 120 × 8 ≈ 8.0 Gbps，是前者的8倍。如果接口带宽不足，就必须在分辨率和刷新率之间做取舍。

    常见应用场景：

    • 电竞游戏：优先高刷新率（144Hz+），分辨率可选1080p或2K
    • 3A大作/影音：平衡配置（2K@60-144Hz 或 4K@60Hz）
    • 办公设计：优先高分辨率（4K@60Hz），刷新率要求不高

    简单的讲：分辨率（W x H）决定画面有多清晰，刷新率（Hz）决定画面有多顺滑，两者通过带宽公式相互制约，需要根据接口能力和使用场景权衡选择。
