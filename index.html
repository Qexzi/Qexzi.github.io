一、反射

有一个疑问：反射在原生 Java 里到底是为了处理什么问题？

编译期静态类型系统无法覆盖、但运行时又必须按名字或元数据去操作类和对象”的动态性问题

普通 Java 代码在编译时就必须知道要 new 哪个类、调用哪个方法、访问哪个字段，而反射让程序在运行时才根据类名、方法名、字段名、注解、配置或外部输入，去加载类、获取构造器、创建实例、调用方法、读写字段、检查注解和泛型/继承信息，从而让框架和基础设施代码能够用一套通用逻辑处理任意类型，而不是为每个业务类写死代码。

典型场景包括 Spring 这类容器根据配置实例化 Bean 并注入依赖、JSON/ORM 框架按字段名序列化和映射对象、JUnit 发现并执行带 @Test 的方法、JDBC 通过类名加载驱动、动态代理在方法调用前后织入逻辑、插件系统按字符串加载实现类，以及测试和工具代码访问私有或受保护成员。

它还要处理类加载时机、访问权限、泛型擦除后信息有限、注解保留策略、异常包装、性能开销、安全限制和 Java 模块化下的开放性问题。但反射本身不实现业务逻辑，它只是提供“运行时动态访问类型信息与成员”的能力；能用接口多态、工厂、函数式接口等静态手段解决的地方通常不该用反射，反射主要留给框架、容器、序列化、代理、测试工具这类必须在编译期对未知类型做通用处理的底层代码。

1. 复现

Nginx 解析漏洞
Nginx 是一款 Web 服务器，可以作为反向代理、负载均衡、邮件代理、HTTP 缓存等。这个 Vulhub 环境包含一个由用户配置不当导致的解析漏洞。

版本信息：

  • Nginx 1.x 最新版
  • PHP 7.1.x 最新版

由此可知，该漏洞与 Nginx、PHP 版本无关，属于用户配置不当造成的解析漏洞。

该漏洞存在的原因是 Nginx 在配置中对文件扩展名的处理方式。当请求一个具有多个扩展名的文件（如 file.jpg.php）时，Nginx 可能会根据最后一个扩展名来处理，即使该文件最初是作为图片上传的。
